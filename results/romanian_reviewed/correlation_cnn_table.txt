The image count matters: the matrix has rank at most (images - 1), so
on generation it is strongly degenerate (rank <= 3), while on retrieval it is far
better conditioned (rank <= 24).

MATRIX VARIANTS (generation only)

The original code correlates the DIMENSIONS of the embedding, although the
paper describes correlations between IMAGES. And neither uses the prompt,
even though CLIP offers the text-image similarity for free -- exactly the
signal that says how well the image matches the prompt.

Adding the prompt is a solid gain on both targets. The second language adds
something measurable only on GLIDE, and five times less -- but it is the first
variant in which the predictor is NOT blind to language, because it has a
textual input. Both require an encoder whose text and image embeddings live
in the same space, so xlmr-vitb32, not longclip-b.

Limitation to report: the original code packs the two retrieval matrices
as [2, 512, 512] and uses the AVERAGED target, but the architecture
accepts a single channel, while Table 3 reports per system. The two cannot
be reconciled; the variant compatible with the table was chosen -- one model per
(system, metric). This probably explains the larger deviations on retrieval.
